API: Application Programming interfacte
It defines how software components interact with each other
It defines the following
1.) What requests can be made
2.) How to make them
3.) What responses to expect

Key characteristics
1.) Abstract mechanism
Hide implemntation details while exposing functionality
2.) Service boundaries
Clear boundary definition b/w system components

Core API styles
REST 
-> Resource based
-> Stateless
-> Standardised methods
-> Most common styles

Graphql
-> Query language
-> Single endpoint
-> Operation level
-> Minimal round trips

gRPC
-> Protocal Buffers
-> Service definitions
-> Communication types
-> High perfomrmance
 
Difference between rest and Graphql
REST:
Resource based endpoints
Multiple requests for related data
HTTP methods define operations
Fixed response structures
Explicity verskoning
Buitin http caching
eg: GET /api/v1/users/123

Graph ql:
Single endpoint for all operations
Single request with precose data
Query language defiens operatioms
Client specific response structures
Schema Evalotion without versioning
Application level caching
eg:
query {
    users(id: "123"){
        name,
        posts {title,content}
        followers {name}
    }
}
